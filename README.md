# 零代码工作能力蒸馏器

> 每一次被认真完成的工作，都值得为未来留下一条路。

很多重要的工作只存在于一个人的对话、记忆和临场判断里。零代码工作能力蒸馏器会把这些珍贵的工作瞬间保存下来：从一段或多段工作记录出发，连同用户的最终修正、工具调用、项目文件、Git 差异、生成产物和验证结果，编译成一套真正属于这次工作的能力包。

它交付 Skill、MCP、独立 AI Agent、独立中文 UI 和新手可读的完整说明，让一次成功的完成，成为下一次可以直接走上的熟悉路径。

## 一句话理解

第一次完成任务时，系统记录你的目标、判断、工具和结果；下一次遇到相似任务时，能力包会沿着这条真实路径继续工作。

## 产品承诺

- **看得懂**：用业务标题、任务目标、输入、产出和证据解释系统的理解结果。
- **接得上**：从本机 Codex、网页聊天、项目文件、Git 和历史产物中建立连续上下文。
- **做得到**：把成功工作编译成可以安装、可以启动、可以执行的 Skill、MCP 和 Agent。
- **查得清**：每个重要判断都保留来源、文件、版本、命令、产物和验证记录。
- **带得走**：能力包支持 Windows 换机安装，说明、界面和运行入口一起交付。

## 为什么叫“蒸馏器”

它像一座小型工作蒸馏厂，做三件事：

1. **采集**：把会话、文件、命令、差异、产物和验证放到同一张工作地图上。
2. **提纯**：从反复修正和成功执行中找出真正稳定的步骤，标出证据、优先级和适用条件。
3. **封装**：把提纯后的流程装进 Skill、MCP、Agent 和独立界面，交给下一次任务直接使用。

这也是它最有心意的地方：它记住你怎样判断、怎样动手、怎样检查结果，以及哪些地方值得下一次少走弯路。

你也可以把它理解成一个很认真、但不喜欢夸大的“工作考古学家”：

- 会话是原矿；
- 工具调用是现场脚印；
- 文件修改是施工痕迹；
- Git 差异是前后对照；
- 生成文件是成品；
- 测试和验证是验收记录；
- 能力包就是把这次成功工作装进一个可安装的工具箱。

## 它解决什么问题

很多团队真正拥有的能力，散落在聊天记录里：某个人知道该先看哪些文件，知道什么时候要回滚，知道一个报告怎样才算完成，也知道哪些数据需要谨慎解读。换一个人、换一台电脑、换一个项目，这些经验就容易重新变成“从头再问一遍”。

蒸馏器把这类隐性工作流编译成可审计、可回放、可安装的能力包：

```mermaid
flowchart LR
  A[选择会话] --> B[理解目标与最新修正]
  B --> C[发现项目与相关文件]
  C --> D[连接工具调用与文件变化]
  D --> E[建立证据图谱]
  E --> F[P0-P3 能力建议]
  F --> G[编译 Skill / MCP / Agent]
  G --> H[独立 UI 执行、验证与回滚]
```

## 四个产品层

### 1. 蒸馏主页：给零代码用户

主页只需要回答三件事：

1. 你要蒸馏哪条工作？
2. 系统理解了什么？
3. 生成后能替你完成什么？

本机 Codex 会话、网页端 ChatGPT/DeepSeek/Gemini/豆包会话分开管理。列表显示真实标题、最后目标、更新时间、内容摘要、项目归属和已有产物。支持单选、多选、工作区全选、单条排除，以及按标题和完整内容搜索。

### 2. 蒸馏建议中心：给操作者和业务人员

系统会把“重要、紧急、可信”拆成三种清晰判断，分别显示：

- `P0`：最新纠正、方向冲突、失败验证和核心依赖，必须先处理。
- `P1`：高频、完整、输入输出清楚且有真实产物的核心工作流。
- `P2`：文件、脚本、模板、补采、验证和复用增强。
- `P3`：低置信度候选、一次性探索和待确认流程。

每条建议都有“为什么”、证据引用、置信度、预期产物和下一步动作。用户可以点击“更重视这个目标”或“暂不纳入”，系统会重新计算顺序。

### 3. 可安装能力包：给外部使用者

每个包都是当前会话和项目的专属产品，内容由真实目标、工具链、文件变化和产物共同决定。标准包包含：

```text
README.md                 零代码使用说明
CAPABILITY.md             直白说明能做什么、适合什么、边界在哪里
PRIORITY-PLAN.md          P0-P3 顺序、原因、证据与预期产物
TASK-CATALOG.md           可以直接交给 Agent 的任务清单
recommendation.json       机器可读的能力与优先级
evidence-manifest.json    会话、文件、Git、产物、验证证据索引
skill/SKILL.md            可安装 Skill
mcp/                      可安装 MCP 服务与配置
agent/                    独立执行型 Agent
agent/ui/                 与能力特性匹配的独立中文 UI
```

包名也会从会话主题、实际工具和真实产物中生成，例如：

- `PPT 多版本融合与高质量演示文稿重构能力包`
- `评论与视频数据全量洞察及报告生成能力包`
- `多会话项目证据蒸馏与可安装 Agent 生成能力包`

命名依据会同时写进页面和 `README.md`，使用者可以看到它来自哪些主题、工具、文件和产物。

### 4. 执行型 Agent：给真正要做事的人

生成后的 Agent 具备完整的本地工作闭环，能够从理解任务和制定计划开始，继续完成：

```text
理解任务
  -> 读取工作区与项目规则
  -> 制定可回放步骤
  -> 搜索、读取和修改文件
  -> 执行本地命令
  -> 查看 Git 状态和差异
  -> 运行验证
  -> 展示产物和证据
  -> 失败时重试、恢复或回滚
```

独立 UI 会展示当前任务匹配了哪些 P0-P3 能力、准备读取哪些文件、准备执行哪些命令、实时输出、文件差异、验证结果和生成文件入口。零代码用户只需选择工作区、填写目标、点击“开始执行”。

## 项目理解按需展开

蒸馏器严格区分三种范围：

- **单会话**：只使用所选会话及其直接证据，不带入整个项目背景。
- **多会话**：只合并所选会话，按共同目标、文件、产物和时间线聚类。
- **完整项目**：只有用户明确选择项目文件夹后，才读取项目规则、依赖、Git、相关文件和生成产物。

选择项目后，系统会根据会话证据筛选相关文件，只把与当前目标有关的内容纳入上下文。每份结果都会明确列出纳入项、排除项和排除原因。

## 网页聊天读取

网页端会话与本机 Codex 会话使用独立的来源、持久化目录和搜索索引。支持：

- ChatGPT、DeepSeek、Gemini、豆包的独立来源卡片；
- 浏览器伴侣读取真实网页会话标题、消息、工具事件和媒体调用记录；
- 首次全量读取时显示进度、已读取数量、失败数量和当前会话；
- 任务暂停、继续、取消、失败重试和断点续读；
- 已成功读取的会话保存到本机，下一次“读取当前聊天”会更新对应会话，并保留原有标题、内容和同步记录；
- 3000 条以上网页会话的批量计划、检查点和增量同步。

网页读取使用当前电脑浏览器的登录态完成配对。登录 Cookie、令牌和 API Key不写入能力包、URL、日志或导出文件。

## 证据与质量控制

蒸馏结果保留完整出处。每条能力建议都可以追到：

```text
结论
 -> 指标或步骤
 -> 分类标签与计算方法
 -> 评论、消息或工具事件
 -> 视频、项目文件或 Git 差异
 -> 原始文件与行号
 -> SHA-256 与采集状态
 -> 生成产物与验证结果
```

当前质量门包括：

- 数据身份与用户目标一致性检查；
- 输入文件、字段、格式和哈希检查；
- 内容寻址证据编号，新增记录不会让旧编号漂移；
- 覆盖率、指标可用性和禁止外推条件；
- 失败验证、用户纠正和旧方案冲突的 P0 阻断；
- 原任务回放、留出任务和隔离工作区执行验证；
- 能力包内相对路径、缺失资源和敏感信息检查。

## 换机安装

Windows x64 用户可以使用发布页提供的单文件安装器：

1. 双击 `work-capability-distiller-windows-x64-setup.exe`。
2. 安装器自动解压、检查并安装到当前用户目录。
3. 安装完成后自动打开主工作台。
4. 新电脑重新发现本机 Codex 会话，并重新连接浏览器网页聊天。

备用 ZIP 包内还提供：

```text
安装并启动.cmd       首次安装或升级
直接启动.cmd         从当前解压目录直接运行
检查安装包.cmd       完整性与隐私自检
修复安装.cmd         修复入口和当前安装检查
回滚上一版本.cmd     恢复升级前版本
使用说明.html        面向新手的图形化说明
```

换机包不携带旧电脑的会话、项目文件、生成产物、Cookie、令牌或 API Key。旧电脑生成的能力包可以作为独立 ZIP 复制到新电脑，再从主工作台导入。

## 本地开发

### 运行主工作台

```powershell
npm install
npm run session:ui
```

默认打开 `http://127.0.0.1:8794/`。启动器会在 `8960-8999` 范围内自动选择可用端口。

### 运行前端与业务服务

```powershell
npm install
Copy-Item .env.example .env
npm run dev:all
```

### 运行测试

```powershell
npm run test:session-forensics
```

重点测试覆盖：会话来源索引、正文搜索、网页增量同步、断点续读、多会话项目拆分、证据图谱、能力包编译、独立 Agent 执行、换机安装、自检、升级保留和回滚入口。

## 隐私和使用边界

蒸馏器默认只在本机 `127.0.0.1` 提供服务。它不会把本机聊天、项目文件、Cookie、令牌或模型密钥写入发布包。文件修改和命令执行由独立 Agent 的工作区、权限和执行设置控制；每个执行任务都应保留计划、日志、差异、验证和恢复点。

对于身份不一致、证据不足、覆盖率过低或验证失败的输入，系统会生成受限建议或阻断发布，并明确标出不确定范围。

正式发布时建议同时提供：

- Windows x64 ZIP 备用包；
