# 换机一键安装与数据迁移说明

## 交付形态

当前正式交付物是 Windows x64 换机 ZIP。压缩包内置 Node.js 运行环境，目标电脑不需要预装 Node.js、Git 或项目依赖。

解压后有三种入口：

- `安装并启动.cmd`：首次安装使用。复制到当前用户目录，执行安装后自检，创建桌面和开始菜单入口，并打开主工作台。
- `直接启动.cmd`：不安装到用户目录，直接从当前文件夹启动，适合试用或放在移动硬盘上运行。
- `检查安装包.cmd`：只执行完整性和隐私清单检查，不启动服务。

## 新电脑操作流程

1. 下载并完整解压 ZIP，不要直接在压缩包预览窗口运行文件。
2. 双击 `安装并启动.cmd`。
3. 等待安装后浏览器自动打开 `http://127.0.0.1:8960/` 到 `http://127.0.0.1:8999/` 范围内的本机地址。
4. 在主工作台选择新电脑上的本机 Codex 会话，或连接浏览器网页聊天。
5. 首次连接网页聊天时只需完成一次浏览器配对；后续从主工作台点击对应平台即可更新会话列表。

## 换机后的数据边界

安装包不携带旧电脑的聊天记录、项目文件、生成产物、Cookie、令牌、API Key 或浏览器登录信息。

这些内容在新电脑上分别处理：

- 本机 Codex 会话：从新电脑本机路径自动发现；路径变化时通过页面选择工作区或会话目录。
- 项目文件：只在用户明确选择项目模式时读取；单会话蒸馏不会自动带入整个工作区。
- 网页聊天：使用新电脑浏览器已有的登录状态；安装包不会复制登录态。
- 已有能力包：将旧电脑导出的能力包 ZIP 单独复制到新电脑，在结果页导入并执行包内自检。

## 安装、升级和修复

安装目录默认为 `%LOCALAPPDATA%\\WorkCapabilityDistiller`。升级会先复制到临时版本目录，执行完整性检查后再切换为新版本；安装前版本保留在 `%LOCALAPPDATA%\\WorkCapabilityDistiller.previous`。工作台已生成的 `output` 数据会带入新版本，包括网页会话缓存、蒸馏结果和能力包。

遇到启动问题时按顺序处理：

1. 双击 `检查安装包.cmd`，确认内置运行环境和主界面文件完整。
2. 双击 `修复安装.cmd`，重新创建桌面入口并再次检查当前安装。
3. 若刚升级后发现异常，先关闭运行中的工作台，再双击 `回滚上一版本.cmd` 恢复上一版本。
4. 检查 8960-8999 端口是否被其他程序占用，启动器会自动选择范围内的可用端口。
5. 使用 `直接启动.cmd` 验证当前解压目录是否可运行。
6. 仍有问题时保留启动窗口中的错误信息和 `version.json`，用于定位版本和环境。

## 发布验收

每个换机包在发布前必须通过：

- 内置 Node.js 可执行文件存在且可启动。
- 主工作台 HTML、JavaScript、样式和服务端文件齐全。
- 隐私清单中的会话、项目、产物、浏览器认证和 API Key 均为 `false`。
- 解压后自检通过。
- 首次安装、同版本覆盖安装和保留 `output` 数据的升级安装均通过。
- 升级后存在 `installed-version.json` 与上一版本目录，修复和回滚入口可见。
- 便携启动后 `/api/health` 返回成功。
- 桌面和开始菜单入口指向当前安装目录。
- Windows 10/11 x64 新用户目录可完成安装并打开主工作台。

当前包的机器可读信息位于 `version.json`，版本和构建时间以该文件为准。
