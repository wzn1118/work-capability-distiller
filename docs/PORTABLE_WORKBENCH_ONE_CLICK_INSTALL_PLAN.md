# 换机一键安装与持续升级方案

## 目标

让用户把安装包复制到另一台 Windows x64 电脑后，只完成一个动作：双击安装器。安装器负责准备运行环境、安装主工作台、创建入口、启动服务并打开浏览器；用户随后只需要选择新电脑上的会话、项目和网页聊天连接。

交付对象是 aftercode 本体，包含：

- 主蒸馏台与三视图导航；
- 本机 Codex 会话发现、搜索和多选；
- ChatGPT、DeepSeek、Gemini、豆包网页会话连接；
- 项目、文件、Git、产物和验证证据理解；
- P0-P3 建议、能力包生成和独立 Agent；
- Windows x64 内置 Node.js 运行环境；
- 安装、自检、升级、修复和回滚入口。

## 用户路径

### 新电脑首次安装

1. 下载 `aftercode-windows-x64-setup.exe`，或下载 ZIP 备用包。
2. 双击单文件安装器。
3. 安装器解压临时载荷并运行包内自检。
4. 新安装默认进入 `%LOCALAPPDATA%\\aftercode`；检测到旧版 `%LOCALAPPDATA%\\WorkCapabilityDistiller` 时原地升级。
5. 创建开始菜单、桌面和维护入口。
6. 启动本地服务并打开 `127.0.0.1` 工作台。
7. 工作台自动发现当前电脑可用的 Codex 会话。
8. 用户按需连接浏览器网页聊天并读取真实会话。

### ZIP 备用路径

ZIP 包适合没有管理员权限、企业安全策略限制单文件安装器、或需要人工审查文件的场景：

1. 解压 ZIP 到普通文件夹。
2. 双击 `安装并启动.cmd`。
3. 安装器复制到用户目录并创建入口。
4. 也可以直接双击 `直接启动.cmd`，从解压目录运行而不安装。

## 包体结构

```text
aftercode-windows-x64-<版本>/
  runtime/
    node.exe                         内置 Node.js 运行时
    *.dll                            Windows 运行依赖
  session-forensics/
    ui-server.mjs                    主蒸馏台服务
    ui/                               主蒸馏台界面
    lib/                              会话、项目、证据和能力编译逻辑
    templates/                        Agent、MCP 和浏览器伴侣模板
  portable-launcher.mjs              端口选择、服务启动和浏览器打开
  portable-installer.mjs             安装、升级、保留产物和版本切换
  portable-self-check.mjs            包体完整性和隐私清单检查
  install-and-start.cmd              安装或升级入口
  start-workbench.cmd                已安装目录启动入口
  uninstall.cmd                      卸载入口
  repair-install.cmd                 修复入口
  rollback-previous.cmd              回滚入口
  使用说明.html                       新手说明
  version.json                       版本、平台和数据政策
  run-state.json                     工作台运行期间的临时状态
```

## 安装器状态机

```text
读取安装包
  -> 自检必要文件和隐私清单
  -> 读取旧版 run-state.json
  -> 停止由本包启动的旧工作台
  -> 创建 <目标>.next 临时目录
  -> 复制新版本并跳过包内 output
  -> 从旧安装复制 output 持久化产物
  -> 对临时目录执行第二次自检
  -> 旧目录改名为 <目标>.previous
  -> 临时目录切换为正式目标目录
  -> 写入 installed-version.json
  -> 创建桌面和开始菜单入口
  -> 启动主工作台
```

任何一步失败都保留当前正式安装。新版本只有通过自检后才会替换旧目录。

## 运行状态与升级安全

启动器运行后写入 `run-state.json`，记录：

- 启动器 PID；
- 工作台服务 PID；
- 绑定端口；
- 本地 URL；
- 安装根目录；
- 启动时间。

升级前安装器只处理根目录与当前安装一致的状态文件，并先停止对应的启动器和服务进程。旧版本状态文件失效或目录不匹配时会跳过，不接触其他程序。

工作台退出后会清理自己的状态文件。状态文件属于运行控制信息，不进入能力包、日志导出或会话证据。

## 数据迁移边界

### 默认迁移内容

- `output/` 下的蒸馏结果和能力包产物；
- 当前安装的版本信息；
- 用户已经生成的报告、证据和任务快照。

### 新电脑重新发现的内容

- 本机 Codex 会话目录；
- 新电脑上的项目和 Git 仓库；
- 新电脑浏览器中的网页聊天登录状态；
- 本机可用的 Node、Python、Git 和其他工具链；
- 用户在新电脑上重新选择的工作区。

### 默认不迁移的内容

- Cookie、浏览器令牌和登录状态；
- API Key、Authorization 和模型密钥；
- 旧电脑的用户目录绝对路径；
- 未明确导出的本机聊天原文；
- 项目源文件副本和临时缓存。

这种边界保证换机包可以公开传递，也避免把旧电脑环境错误带到新电脑。

## 版本升级与回滚

### 升级

- 安装器写入 `<目标>.previous`；
- 当前 `output/` 先复制到新版本；
- 新版本自检通过后才切换；
- `installed-version.json` 保存当前实际安装版本；
- 升级过程不覆盖已生成的报告和能力包。

### 回滚

`回滚上一版本.cmd` 执行以下动作：

1. 确认存在上一版本运行时。
2. 停止当前工作台。
3. 当前目录移动到 `.failed-rollback`。
4. `.previous` 移回正式目录。
5. 启动恢复后的工作台。
6. 保留失败版本目录供诊断。

### 修复

`修复安装.cmd` 会重新执行自检并重建桌面入口。它不覆盖用户产物，也不改变网页聊天登录状态。

## 自检门槛

安装包自检检查：

- 内置 Node.js 是否存在；
- 主服务、主界面、模板和启动器是否存在；
- `version.json` 是否可解析；
- 数据政策中的会话、项目文件、生成产物、Cookie、令牌和 API Key 标记是否全部为 `false`；
- 新版本临时目录是否可以独立启动；
- 安装后的工作台是否返回本地健康状态；
- 浏览器主页是否能显示中文主蒸馏台标题。

## 跨电脑验收矩阵

| 场景 | 验收结果 |
|---|---|
| 空白 Windows x64，双击单文件安装器 | 安装、启动、打开浏览器成功 |
| 空白 Windows x64，ZIP 解压启动 | 安装入口和直接启动入口均可用 |
| 无 Node.js、无 Git | 工作台仍能启动，缺少工具时给出直白提示 |
| 已安装旧版本并存在 `output/` | 升级后产物保留 |
| 升级时旧工作台仍在运行 | 安装器停止本包旧进程后继续切换 |
| 新版本自检失败 | 旧安装保持原状 |
| 回滚上一版本 | 旧版本恢复，失败版本保留 |
| 本机已有其他本地服务 | 自动选择 `8960-8999` 范围内可用端口 |
| 首次连接网页聊天 | 页面显示配对和读取状态 |
| 新电脑没有旧项目路径 | 会话列表可用，项目上下文要求重新选择 |
| 安装包被解压到包含中文和空格的目录 | 安装、启动和自检成功 |

## 发布流程

每个正式版本发布前固定执行：

```powershell
npm ci
npm run build
npm run test:server
npm run test:session-forensics
npm run test:portable
node session-forensics/build-portable-workbench.mjs
```

发布物包括：

- Windows x64 单文件安装器；
- Windows x64 ZIP 备用包；
- `version.json`；
- SHA-256 校验清单；
- 版本变更说明；
- 空白 Windows 虚拟机验收记录。

GitHub Actions 使用 Ubuntu 与 Windows 双作业：Ubuntu 负责构建、服务端和蒸馏器全套测试，Windows 负责真实换机安装包测试。

## 面向新手的最终说明

用户只需要记住三句话：

1. **第一次换电脑：双击安装器。**
2. **安装完成后：选择当前电脑的会话和项目。**
3. **网页聊天：在工作台点击对应平台并按提示连接。**

所有运行环境、端口选择、文件检查、升级保留、回滚和错误恢复都由安装器和主工作台处理。
